# 後端任務執行規範

## 1. 適用方式

1. 本規範用於執行已確認任務文件中的後端核心開發 task。
2. 使用本規範前，必須先載入 `general` execute，再載入 `backend` execute。
3. 本規範只補充後端特有的執行要求；未涵蓋事項依 `general` execute 處理。
4. 若本規範與 `general` execute 衝突，以後載入且更具體的本規範為準。
5. 系統、平台、安全、權限及其他更高優先級規則不受前項影響。
6. 本規範保持技術中立；特定語言、框架及工具的要求由後續階層補充。
7. 執行者只負責執行指定 task 及記錄結果，不得規劃、補充或改寫任務規格。

## 2. 核心範圍

1. 本規範適用於下列後端核心開發領域：
   1. 服務或模組責任範圍內的實作。
   2. API 或事件契約。
   3. 業務邏輯與錯誤處理。
   4. 資料模型與資料存取。
   5. schema、migration 及必要資料轉換。
   6. 外部系統整合。
   7. 身分驗證、授權及核心安全需求。
   8. 與指定後端成果直接相關的測試及驗證。
2. 只有指定 task 明確列出的領域才可執行。
3. 不適用的領域不得因本規範列出而納入執行範圍。

## 3. 排除範圍

1. 下列工作不屬於本規範的執行範圍：
   1. 部署與發布。
   2. 基礎設施建立或修改。
   3. 執行環境佈建。
   4. 監控平台或告警配置。
   5. 日常維運程序。
   6. 前端或用戶端實作。
   7. 第三方或其他內部服務的實作。
2. 指定 task 包含排除範圍內的工作時，必須停止並指出衝突項目。
3. 不得跳過排除項目後繼續執行其餘步驟。
4. 後端成果依賴排除範圍內的工作時，只能依 task 記錄的契約、前置條件及責任邊界進行。

## 4. 後端 task 完整性檢查

1. 除 `general` execute 要求的完整性檢查外，執行前必須確認 task 已依適用範圍明確定義：
   1. 服務或模組的責任與邊界。
   2. 呼叫者、消費者及相依系統。
   3. 輸入、輸出、錯誤及失敗行為。
   4. API 或事件契約及相容性要求。
   5. 資料所有權、初始狀態、生命週期及存取責任。
   6. 交易邊界、一致性、冪等性、排序及併發要求。
   7. 外部整合契約、超時、重試及失敗處理。
   8. 身分驗證、授權及敏感資料處理限制。
   9. 預計修改的精確檔案。
   10. 固定順序的執行步驟。
   11. 完整命令、預期輸出及驗證方式。
2. 只有實際影響指定成果的項目需要適用。
3. 必要資訊缺漏、不明確或彼此矛盾時，必須停止並要求先依 task 規劃規範維護任務文件。
4. 執行者不得：
   1. 自行設計契約、資料模型或安全規則。
   2. 自行選擇框架、資料庫、通訊協定或工具。
   3. 依專案慣例補足 task 未指定的實作決策。
   4. 自行補充檔案、命令、參數或驗證方式。
   5. 在多條未指定選擇條件的實作路徑中自行選擇。

## 5. 執行邊界

1. 只能修改指定 task 明列的精確檔案。
2. 只能依 task 指定的固定順序執行步驟。
3. 只能執行 task 明列的具副作用命令及外部操作。
4. 不得修改其他服務、前端、用戶端或外部系統的實作。
5. 不得順便修正相關問題、更新依賴、重構或格式化無關內容。
6. 完成 task 需要新增檔案、命令、外部操作或技術決策時，必須停止並要求先維護任務文件。
7. 發現 task 與實際後端架構、契約、資料狀態或工具不一致時，必須停止。
8. 發現未預期變更時，依 `general` execute 的外部修改處理規則停止，不得自行整合或覆寫。

## 6. API 與事件契約

1. 執行 API 或事件契約變更前，必須確認 task 已明確指定：
   1. 契約用途及消費者。
   2. 輸入、輸出及錯誤行為。
   3. 權限要求。
   4. 相容性或版本限制。
   5. 預計修改的契約檔案。
   6. 契約驗證方式及通過條件。
2. 必須完全依 task 指定的契約內容實作。
3. 不得自行新增欄位、端點、事件、錯誤碼或相容性策略。
4. 契約變更需要同步修改未列入 task 的消費者時，必須停止。
5. 必須執行 task 指定的契約驗證，不得以人工判斷或其他測試替代。

## 7. 業務邏輯與資料存取

1. 必須依 task 指定的責任邊界、輸入、輸出及錯誤行為完成最小實作。
2. 不得自行改變既有模組、服務或資料所有權。
3. 涉及資料存取時，必須依 task 指定的：
   1. 資料來源與初始狀態。
   2. 讀取及寫入責任。
   3. 完整性與一致性要求。
   4. 交易邊界。
   5. 併發及失敗行為。
4. task 未定義必要資料行為時，必須停止。
5. 不得以暫時停用驗證、降低檢查標準或加入無效實作的方式完成 task。

## 8. Schema、migration 與資料轉換

1. 執行 schema、migration 或資料轉換前，必須確認 task 已指定：
   1. 精確檔案。
   2. 固定執行順序。
   3. 初始 schema 或資料狀態。
   4. 預期 schema 或資料結果。
   5. 驗證方式。
   6. 失敗停止條件。
   7. 回復方式及其授權要求。
2. 不得對正式環境或正式資料執行操作。
3. 不得執行破壞性資料操作。
4. migration 具有不可逆、資料遺失或相容性風險時，必須確認 task 已列出保護措施；缺少時必須停止。
5. 發生失敗時，依 `general` execute 的失敗處理規則停止，不得自動 rollback。
6. rollback 需要另行授權，且不得違反更高優先級的禁止事項。

## 9. 外部系統整合

1. 執行外部整合前，必須確認 task 已指定：
   1. 整合目的與責任邊界。
   2. 輸入、輸出及錯誤行為。
   3. 認證與授權方式。
   4. 相容性限制。
   5. 超時、重試及失敗處理。
   6. 驗證環境與外部操作。
2. 不得自行假設外部系統的能力、契約或可用性。
3. 不得連線或變更 task 未明列且未獲授權的外部服務。
4. 不得將機密資料寫入程式碼、設定、命令、紀錄或回報。
5. 外部依賴狀態與 task 記載不一致時，必須停止。

## 10. 身分驗證與核心安全

1. 涉及安全行為時，必須確認 task 已指定：
   1. 身分驗證責任。
   2. 授權規則與資源邊界。
   3. 敏感資料處理限制。
   4. 不可信輸入的驗證要求。
   5. 安全驗證方式及通過條件。
2. 不得自行放寬驗證、授權、資料隔離或敏感資料保護要求。
3. 權限變更必須依 task 驗證適用的：
   1. 合法存取。
   2. 未驗證存取。
   3. 權限不足存取。
   4. 跨資源或跨租戶存取。
4. 必要安全情境未定義或無法驗證時，必須停止。
5. 不得讀取、顯示、寫入或傳送密碼、API 金鑰、存取權杖、私鑰、個人資料或其他機密資訊。

## 11. 後端驗證

1. 必須完整執行 task 指定的後端驗證。
2. 適用的驗證可以包含：
   1. 單元測試。
   2. 整合測試。
   3. API 或事件契約驗證。
   4. 資料完整性與 migration 驗證。
   5. 身分驗證與授權驗證。
   6. 品質屬性驗證。
   7. 編譯、建置、格式檢查、靜態分析及型別檢查。
3. 不得新增、刪除、替換或跳過 task 指定的驗證。
4. 不得自行縮小驗證範圍或降低通過條件。
5. 驗證具有資料、本機或外部副作用時，只能依 task 明列且已獲授權的方式執行。
6. 任一驗證無法執行或首次出現非預期失敗時，必須立即停止。
7. 未取得全部指定驗證的客觀證據時，不得建議將 task 標記為「已完成」。

## 12. 後端停止條件

1. 發生下列任一情況時，必須立即停止：
   1. 後端 task 必要資訊缺漏、不明確或矛盾。
   2. task 與來源 plan、專案現況或適用規範不一致。
   3. 必要契約、資料或安全決策未確認。
   4. 完成成果需要 task 未列出的檔案、命令或外部操作。
   5. 需要自行選擇技術、架構或實作路徑。
   6. 發現未預期的工作區、schema、資料或外部狀態。
   7. 需要處理本規範的排除範圍。
   8. 命令、步驟或驗證首次出現非預期失敗。
   9. 需要讀取、顯示、寫入或傳送機密資料。
2. 停止後必須依 `general` execute 回報證據、目前狀態、剩餘風險及解除條件。
3. 不得自行重試、修正、回復、改採其他方法或繼續後續步驟。

## 13. 完成條件

1. 只有下列條件全部成立時，才可建議將指定 task 更新為「已完成」：
   1. 所有後端實作均在 task 明列範圍內完成。
   2. 實際修改檔案與 task 規格一致。
   3. 所有指定命令及外部操作均依固定順序完成。
   4. 所有指定驗證均已執行並符合客觀通過條件。
   5. 契約、資料、安全及相容性要求均有實際證據。
   6. 未發生未記錄的規格差異。
   7. 已記錄未驗證項目與剩餘風險。
2. task 狀態、attempt 紀錄及任務文件狀態依 `general` execute 的第二次授權流程更新。
3. 在取得第二次明確授權並完成狀態寫入前，不得宣稱任務文件已完成更新。
