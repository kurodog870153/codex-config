# 後端任務規劃規範

1. 規劃前唯讀確認專案架構、測試慣例及可用工具；TASK 必須固定單一契約、責任邊界、資料、交易及錯誤行為，只記必要架構決策或核准例外。
2. 需要某測試的首個 TASK 必須同時建立或修改該測試與最小實作；測試只能來自目前基線、明確相依的前序 TASK 或目前 TASK，不得由後序或最終驗證 TASK 回補。
3. 可自動化的行為變更在同一 TASK 依序執行 Red、Green、Refactor；Red 與 Green 使用獨立 VAL 且可共用 CMD，Red 須預定目標測試及因功能未實作而失敗的條件。
4. Red 只是暫時狀態；TASK 完成時累積工作區必須通過全部適用驗證。
5. 可重現的相關測試放入實作 TASK；需資料庫、Redis、特定本機檔案或外部服務的完整回歸另建具明確前置條件的驗證 TASK。
6. 不得為通過驗證排除、停用、替換或延後必要測試；只列適用測試，高影響測試省略且原因不明顯時簡述原因。
