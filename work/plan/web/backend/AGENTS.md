# 後端計畫規劃規範

## 1. 適用方式

1. 本規範用於根據 big picture 產生或維護後端核心開發計畫。
2. 使用本規範前，必須先載入 `general` plan，再載入 `backend` plan。
3. 本規範只補充後端特有要求；未涵蓋事項依 `general` plan 處理。
4. 若本規範與 `general` plan 衝突，以後載入的本規範為準。
5. 計畫必須保持技術中立，除非使用者已確認特定技術限制或決策。

## 2. 核心範圍

1. 後端計畫只規劃下列核心開發領域：
   1. 服務邊界與責任。
   2. API 或事件契約。
   3. 資料模型與資料存取。
   4. 外部系統整合。
   5. 身分驗證、授權及核心安全需求。
2. 各領域必須依實際需求判斷是否適用。
3. 不適用的領域必須簡短說明原因。
4. 禁止為了涵蓋所有領域而虛構需求、交付成果或風險。

## 3. 職責邊界

1. 後端計畫負責定義需要達成的後端能力、責任邊界、交付成果及驗收依據。
2. 後端計畫只列出里程碑所需的高階工作項目。
3. 禁止展開成下列內容：
   1. 程式碼或具體實作步驟。
   2. 檔案或類別層級的修改清單。
   3. 指令、套件安裝或工具操作。
   4. task 或子任務拆解。
4. 部署、發布、基礎設施及日常維運不屬於本規範範圍。
5. 若後端成果依賴部署或維運能力，只能記錄其契約、前置條件及阻塞影響，不得規劃其實作。

## 4. 後端需求釐清

1. 除 `general` plan 的需求釐清項目外，必須依需求確認：
   1. 服務或模組的責任與邊界。
   2. 呼叫者、消費者及相依系統。
   3. 輸入、輸出、錯誤及失敗行為。
   4. 資料所有權、來源、生命週期及存取需求。
   5. 外部整合的責任與契約。
   6. 身分驗證、授權及敏感資料處理需求。
2. 下列品質屬性只有在會影響核心設計、範圍、交付成果或驗收時才需釐清：
   1. 一致性。
   2. 交易邊界。
   3. 冪等性。
   4. 相容性。
   5. 效能。
   6. 併發行為。
3. 未確認且會影響計畫的後端決策，必須列入「待確認事項」。
4. 禁止自行假設框架、資料庫、通訊協定、部署平台或基礎設施。

## 5. 服務邊界與責任

1. 適用時，計畫必須說明：
   1. 後端能力的責任範圍。
   2. 不由該能力負責的事項。
   3. 上游與下游依賴。
   4. 與其他服務或模組的責任分界。
2. 跨系統依賴必須記錄契約、資料交換、責任歸屬及阻塞條件。
3. 禁止在後端計畫中規劃前端、第三方服務或其他內部服務的具體實作。

## 6. API 與事件契約

1. 適用時，計畫必須涵蓋：
   1. 契約的用途與使用者。
   2. 輸入與輸出的必要行為。
   3. 錯誤與失敗行為。
   4. 權限要求。
   5. 相容性或版本限制。
2. 若冪等性、排序、重試或重複傳遞會影響成果，必須列入需求或驗收標準。
3. 計畫只定義契約成果與驗收方式，不展開端點、欄位或事件結構的實作細節。

## 7. 資料模型與資料存取

1. 適用時，計畫必須涵蓋：
   1. 資料所有權。
   2. 核心資料關係與完整性要求。
   3. 讀取及寫入責任。
   4. 一致性與交易需求。
   5. 資料生命週期及必要的相容性要求。
2. 若既有資料需要轉換或演進，只規劃後端資料成果、限制及驗收條件。
3. 禁止在 plan 中展開資料表、欄位、索引或遷移指令等實作細節。

## 8. 外部系統整合

1. 適用時，計畫必須說明：
   1. 整合目的。
   2. 系統間責任邊界。
   3. 輸入、輸出及失敗行為。
   4. 已確認的相容性限制。
   5. 會阻塞里程碑的外部依賴。
2. 不得自行假設外部系統能力、可用性或契約。
3. 外部依賴尚未確認時，計畫必須維持草案並列入待確認事項。

## 9. 核心安全需求

1. 適用時，計畫必須涵蓋：
   1. 身分驗證責任。
   2. 授權規則與資源邊界。
   3. 敏感資料的處理限制。
   4. 不可信輸入及越權風險。
2. 安全需求必須轉換為可驗證的交付成果或驗收標準。
3. 禁止在 plan 中記錄密碼、金鑰、權杖、私鑰或其他機密資料。

## 10. 後端交付成果

1. 除 `general` plan 的交付成果規則外，後端交付成果應依需求包含：
   1. 已確認的服務能力或責任邊界。
   2. 可供消費者採用的 API 或事件契約。
   3. 符合完整性與一致性要求的資料能力。
   4. 符合責任邊界的外部整合能力。
   5. 符合驗證與授權要求的安全能力。
2. 每項成果只能在適用時納入。
3. 活動、技術選型或實作方式不得單獨作為交付成果。

## 11. 後端驗收標準

1. 每項後端交付成果必須要求適用且可觀察的驗證證據。
2. 驗證證據可依成果包含：
   1. 契約驗證。
   2. 整合行為驗證。
   3. 資料完整性或一致性驗證。
   4. 身分驗證與授權驗證。
   5. 已確認品質屬性的驗證。
3. 驗收標準必須描述驗證對象、方式、預期結果及客觀通過條件。
4. 計畫不得指定測試命令、測試檔案或測試實作細節。
5. 不適用的驗證類型不得強制加入。

## 12. 後端里程碑

1. 里程碑應依可驗收的後端能力或契約成果拆分。
2. 里程碑必須標示與其他服務、前端或外部系統之間的必要依賴。
3. 相依方的具體工作不得納入後端里程碑。
4. 部署、發布及維運活動不得作為後端里程碑。

## 13. 後端風險

1. 除 `general` plan 的風險規則外，應依需求評估：
   1. 服務責任邊界不清。
   2. 契約或相容性尚未確認。
   3. 資料所有權或一致性要求不明。
   4. 外部整合能力或責任未確認。
   5. 驗證、授權或敏感資料處理需求不明。
2. 只有會實質影響目標、範圍、交付成果、里程碑或驗收的風險才可納入。
3. 禁止為了填滿章節而建立假設性風險。
